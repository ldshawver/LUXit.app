# LUX Marketing Platform - Project Documentation

## Overview
LUX Marketing is a multi-channel marketing automation platform designed to streamline marketing efforts. It features a tile-based dashboard with 11 AI agents and AI-powered campaign generation using GPT-4o. The platform aims to be a launch-ready, automated marketing solution offering centralized management for all integrations and API keys, robust social media publishing, and comprehensive contact capture. It includes advanced error logging, diagnostics, and an AI chatbot with auto-repair capabilities to ensure seamless operation. The business vision is to provide an all-in-one, automated marketing solution, tapping into the growing demand for AI-driven marketing tools.

## User Preferences
- Black background with purple, cyan, pink branding
- Launch-ready with all features on Replit and VPS
- Automated systems that work without manual intervention
- Clear error diagnostics and auto-repair capabilities
- Centralized API keys & secrets management (not scattered modal dialogs)
- All social media platforms available in Settings → Integrations for all companies

## System Architecture
The platform is built around a tile-based dashboard with 11 AI agents, leveraging GPT-4o for AI-powered campaign generation. The UI/UX features a pure black background accented with brand colors (purple, cyan, pink), utilizing a comprehensive design system with glassmorphism elements and semantic CSS tokens for consistent branding and theming. Authentication is handled via Replit Auth OAuth (Google, GitHub, Apple, email) with JWKS-based JWT verification.

Key architectural decisions and features include:
- **Admin Approval Queue System**: Mandatory approval workflow for marketing content with status tracking, feature toggles, and an immutable audit log.
- **Social Media Integrations**: Full OAuth 2.0 implementations for various platforms supporting publishing, media listing, insights, and secure token management.
- **Centralized API Keys & Secrets Management**: Dedicated section for secure, encrypted storage and management of API keys and secrets per company. Company model has `set_secret(key, value)` / `get_secret(key)` / `delete_secret(key)` methods that encrypt/decrypt via `services.secret_vault.vault` (Fernet). Supports 2-arg `(key, value)` and 3-arg `(provider, sub_key, value)` call styles. CompanySecret table has a unique constraint on `(company_id, key)` and stores Fernet-encrypted values. The `/api/company/<id>/secrets` GET returns masked values only; POST `/secrets/save` encrypts before storing.
- **Contact Management**: Zapier webhook integration for authenticated contact capture, auto-segmentation, comprehensive customer profiles with lead scoring, activity timelines, and bidirectional sync with newsletter subscribers.
- **Error Logging & Diagnostics**: Robust system for logging application errors to a database with detailed diagnostics.
- **AI Chatbot with Auto-Repair**: Marketing assistant and troubleshooter analyzing server logs and triggering automated error repair.
- **Modular Layout**: 224px left sidebar and a horizontal category tab bar for navigation, with notification and inbox systems providing real-time updates.
- **Feature Toggle System**: Manages per-company feature flags for AI agents, channels, automation, and safety controls, including emergency stop capabilities.
- **CRM Hub**: Action-oriented coaching system with pipeline stages, "Next Actions" widgets, and a visual Kanban pipeline for deal management.
- **SaaS Command Center** (`/saas`): Internal CRM for managing LUXit SaaS customers. Blueprint: `saas_mgmt.py`. Template: `templates/saas/dashboard.html`. Models: `SaasLicense`, `CustomerOnboardingProject`, `CustomerOnboardingTask`, `SaasAutomationLog`. Company model extended with Stripe/Supabase/MyPayLink/n8n IDs + billing status fields. Stripe webhook handler at `POST /api/stripe/webhook` (5 events wired: checkout.session.completed → active, invoice.payment_succeeded → active, invoice.payment_failed → grace_period, customer.subscription.updated → mirror, customer.subscription.deleted → canceled). Hardened with raw-body HMAC signature verification (Stripe SDK v15.1.0), atomic idempotency claim via unique `stripe_event_id` index (race-safe; failed/stale-processing rows are reclaimed for retry, terminal rows return 200 with separate `status='duplicate'` audit row), 5xx response on processing failure so Stripe retries transient errors, payload sanitization (`_sanitize_payload` redacts `client_secret`/`card`/`cvc`), strict prod mode (rejects unsigned events with 503 unless `FLASK_ENV=development` or `DEBUG=true`). `SaasAutomationLog` extended with `stripe_event_id` (UNIQUE), `customer_id`, `subscription_id`, `received_at`, `processed_at`. `/health` exposes `stripe` status (configured/partial/disabled) + `stripe_details.{secret_key,webhook_secret}` booleans (no values). `/health/config.features` exposes `stripe_publishable` and `stripe_webhook` booleans. n8n outbound trigger via `_fire_n8n()` fired on key lifecycle events. 5-tab dashboard: Accounts, Licenses, Onboarding (with 8-task default checklist), Pipeline (SaaS Kanban stages), Automation Log. Navigation: "SaaS" tab added to top catbar and conditional sidebar section. VPS deploy: `python3 vps_deploy_saas_crm.py`. Tests: `tests/test_stripe_webhook.py` (14 passing). Migration: `scripts/migrate_db.py` adds 5 new columns + 3 indexes incl. unique on `stripe_event_id` — must run before first prod webhook.
- **Stripe Subscription Billing** (production system): Customer-facing checkout + portal + lifecycle sync layered on top of the SaaS Command Center webhook. Service module `services/stripe_billing.py` is the single source of truth for tier mapping (`TIER_BY_LOOKUP_KEY = {luxit_starter_monthly: (starter,5), luxit_professional_monthly: (professional,None)}`), the per-seat add-on `luxit_additional_account_monthly`, default 14-day grace window (`BILLING_GRACE_DAYS` overridable), checkout/portal session creators, and `compute_seats_from_subscription()` which sums base plan + add-on quantities. Customer-facing API on `stripe_webhook_bp`: `POST /api/stripe/create-checkout-session` (login-required, accepts `{lookup_key, company_id, user_id}`, **rejects any frontend-supplied price_id/price/amount**, resolves Price by lookup_key server-side, validates company membership, attaches `client_reference_id`+`metadata.lookup_key` to both session and `subscription_data`); `POST /api/stripe/create-portal-session` (login-required, returns to `/app/billing`). Webhook lifecycle now populates: `stripe_price_lookup_key`, `billing_tier`, `billing_status` (active|grace_period|suspended|canceled|incomplete), `max_team_members` (NULL = unlimited), `grace_period_ends_at` (set once on first failed payment, cleared on success), `current_period_start/end`, `cancel_at_period_end`. Tier+seats are applied from `metadata.lookup_key` on `checkout.session.completed` and recomputed from `items[]` on `customer.subscription.updated` so add-on quantity changes flow through. `customer.subscription.deleted` → `billing_status='suspended'`. Customer-facing routes on `main_bp`: `/app/billing` and `/billing` (current plan, status badge, seat usage `n / max` or `n / ∞`, renewal date, "cancels at period end" notice, grace warning, Subscribe / Upgrade / Add Seats / Manage buttons), `/billing/success?session_id=...`, `/billing/cancel`. Template: `templates/billing/billing.html` (uses base.html, vanilla JS POSTs to the two billing endpoints). New `/ready` readiness probe (`routes.py`) returns 200 only when DB is reachable AND `STRIPE_SECRET_KEY` AND `STRIPE_WEBHOOK_SECRET` are set AND `/api/stripe/webhook` route is registered — never echoes secret values. Seat enforcement: `Company.team_member_count` (union of `UserCompanyAccess` + `User.default_company_id`), `Company.team_seats_available`, `Company.can_add_team_member()`; `user_management.add_user` blocks new users when limit is reached and assigns `default_company_id` to admin's company. Migration `scripts/migrate_db.py` adds 8 new company columns: `stripe_price_lookup_key`, `billing_tier`, `billing_status`, `max_team_members`, `grace_period_ends_at`, `current_period_start`, `current_period_end`, `cancel_at_period_end`. Tests: `tests/test_stripe_billing_endpoints.py` (17 cases — checkout auth/lookup_key/price-rejection/happy-path, portal, tier mapping for starter+professional, grace_period_ends_at, add-on seat math, suspension, seat limit enforcement, /ready ok/missing-secret); combined with `tests/test_stripe_webhook.py` → **31/31 passing**. Optional env: `LUXIT_PUBLIC_BASE_URL` (defaults to `https://luxit.app`) for checkout success/cancel + portal return URLs.
- **Autonomous Systems Governor (Orchestrator Agent)**: Master oversight agent with a 6-tab dashboard for system health, agent orchestration, and reporting.
- **Comprehensive Analytics Hub**: Provides 10 metric categories with Chart.js visualizations, including customizable dashboard analytics and predictive analytics (lead scoring, churn risk, send time optimization).
- **Marketing Automations Hub**: Restructured dashboard for email, SMS, and social DM automations, featuring quick-create cards, trigger selection, a 3-step creation wizard, and a rich automation trigger library.
- **SMS Service Integration**: Full Twilio integration for campaigns, bulk sending, and AI-powered content.
- **Multi-Tenant Twilio SMS/Call Platform** (`twilio_sms.py`): Production-ready per-company Twilio platform under `/twilio/*` with encrypted credential storage, conversation threading, auto-reply rules engine (keyword/first-contact/after-hours/stop triggers), business hours, lead auto-capture, missed-call SMS, call log, analytics dashboard, and a full inbox UI. Accessible from sidebar under "SMS Inbox". Webhook endpoints: `POST /twilio/sms/inbound`, `POST /twilio/sms/status`, `POST /twilio/voice/inbound`.
- **Marketing Calendar**: FullCalendar.js integration for managing scheduled posts, SMS, and email campaigns with drag-and-drop rescheduling.
- **AI Auto-Generate for Campaigns**: AI-powered subject line generation and advanced social media post creation features.
- **Email Campaign Builder**: Drag-and-drop builder with content blocks, templates, and A/B testing.
- **User and Company Management**: Includes user profiles, password management, and company-specific branding settings.
- **Onboarding Wizard**: Multi-step process for new company setup, including company info, brand kit, API key configuration, and a launch checklist, with robust file upload validation.
- **In-App Help & Walkthroughs**: Contextual help system with help icons on key screens, slide-out help drawer with instructions/video/PDF, JSON-driven interactive walkthroughs with step highlighting, and onboarding progress tracking (setup/training/docs/go-live readiness). Models: HelpContent, WalkthroughDef, WalkthroughProgress, OnboardingProgress. JS: `static/js/walkthrough.js`. Templates: `templates/partials/help_icon.html`, `help_drawer.html`, `onboarding_progress.html`.
- **Security Enhancements**: Tenant scoping, IDOR protection, CSRF tokens, XSS prevention, and secure cookie configurations.
- **Feedback & Bug Reporting**: Native in-app feedback module. Models `FeedbackTicket` + `FeedbackTicketComment` (models.py ~line 2023). Blueprint `feedback.py` registered after `stripe_webhook_bp` in `app.py` create_app(). Endpoints: `POST /api/feedback` (multipart/JSON; auth-required; optional screenshot), `GET /feedback` (user's own list), `GET /feedback/admin` (filterable: tenant/type/status/priority/date/owner — company admin sees own company, platform admin sees all, regular user redirected), `GET /feedback/<id>`, `GET /feedback/<id>/screenshot` (authenticated file serve), `POST /api/feedback/<id>/{comment,status,assign,priority}`. Types: bug/ux/feature/general. Severities: low/medium/high/critical. Statuses: new/reviewed/priority_fix/in_progress/waiting_user/closed/rejected. Comments support `is_internal=True` (admin-only; submitter posts are silently downgraded to public). Authorization helpers `_can_view_ticket` / `_can_admin_ticket` enforce tenant isolation; cross-tenant assignment rejected. Screenshots are stored under Flask's `instance_path/uploads/feedback/<ticket_id>/` (NOT `/static/`, so they're not publicly fetchable) and served only via `GET /feedback/<id>/screenshot` after the same view-permission check; uploads are validated by magic bytes + extension allowlist (PNG/JPEG/GIF/WebP) with a 5 MB cap. Notifications via `routes.create_notification` + best-effort `EmailService` on submit and status change. Floating "Feedback" FAB injected via `templates/partials/feedback_widget.html` (included in `templates/base.html`); sidebar link under Engagement. Templates: `templates/feedback/{list,dashboard,detail}.html`. Tests: `tests/test_feedback.py` (23 cases — 23/23 passing, incl. magic-byte rejection of `.exe`-renamed-to-`.png` and cross-tenant 404 on screenshot route). New tables auto-created via `db.create_all()` (no migration script needed).
